# Phase 4 — UI Design Contract

> Visual and interaction contract for the schema-driven role edit form (`/roles/{uid}/edit`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase adds **one new page** to an existing Bootstrap 5.3.8 + Turbo 8 + Razor Pages admin tool. The contract below is **derived from the established design language already shipped in Phases 1–3** (`Pages/Roles/Detail.cshtml`, `Pages/Roles/Index.cshtml`, `wwwroot/css/site.css`, `_Layout.cshtml`). The edit form MUST match those surfaces — do not introduce new tokens, colors, or components.

## Spacing Scale

The project uses **Bootstrap's spacer utility scale** (0.25rem base step), which is natively 4px-aligned. Use Bootstrap utility classes (`m*`, `p*`, `gap-*`), not custom CSS.

| Token | Value | Bootstrap class | Usage in this phase |
|-------|-------|-----------------|---------------------|
| xs | 4px | `*-1` (0.25rem) | Icon-to-label gaps, badge spacing |
| sm | 8px | `*-2` (0.5rem) | Inline control gaps (`gap-2`), Uid row spacing |
| md | 16px | `*-3` (1rem) | Default vertical rhythm between form groups (`mb-3`), error summary margin |
| lg | 24px | `*-4` (1.5rem) | Page content padding (`<main class="p-4">`, inherited from `_Layout`), section gaps |
| xl | 32px | `*-5` (3rem) | Major breaks / top offset for centered states (`mt-5`) |

Exceptions:
- **Touch-target minimum: 44px.** All interactive buttons/links carry `style="min-height:44px"` — this is the **established accessibility exception** in this codebase (see Detail/Index pages). Apply it to the Save button, Cancel link, and the Uid copy button. This is intentional and overrides the spacing scale for control height only.
- No other custom pixel spacing. If a value isn't expressible as a Bootstrap utility step, it doesn't belong on this page.

## Typography

Inherits the established hierarchy from Detail/Index pages. **Two weights only** (Bootstrap default 400 + semibold 600 via `fw-semibold`). Sizes are Bootstrap heading defaults relative to the 16px desktop root.

| Role | Size | Weight | Line Height | Applied to |
|------|------|--------|-------------|------------|
| Page heading | `h4` (~22.4px / 1.4rem) | 600 (`fw-semibold`) | 1.2 (BS default) | Form page title "Edit {RoleName}" — matches Detail `<h4 class="fw-semibold mb-3">` |
| Section heading | `h5` (~20px / 1.25rem) | 600 (`fw-semibold`) | 1.2 (BS default) | "Fields" group heading — matches Detail `<h5 class="fw-semibold ...">` |
| Body / input text | 16px desktop / 14px mobile (root, 1rem) | 400 | 1.5 (BS default) | Form labels, input values, error summary text |
| Meta / mono | `small` (~14px / 0.875rem) | 400 | 1.5 | Uid display (`font-monospace small`), field-name labels rendered as `<code>`, helper hints |

Rules:
- Use `<h4 class="fw-semibold">` for the page title and `<h5 class="fw-semibold">` for the field-group heading. No new heading sizes.
- Field schema names display in monospace via `<code>` / `font-monospace small`, consistent with Detail's field table.
- Do not introduce additional font weights, italic emphasis, or letter-spacing.

## Color

Bootstrap 5.3.8 default light theme. No custom palette. The 60/30/10 split maps to the existing shell.

| Role | Value | Bootstrap token | Usage |
|------|-------|-----------------|-------|
| Dominant (60%) | `#ffffff` | body / `bg-white` | Page background, form surface, input fields |
| Secondary (30%) | `#f8f9fa` | `bg-light` / `--bs-light` | Field-label cells, read-only/disabled field backgrounds, sidebar surface |
| Accent (10%) | `#0d6efd` | `btn-primary` / `--bs-primary` | **Reserved — see list below** |
| Destructive / error | `#dc3545` | `--bs-danger` (`alert-danger`, `is-invalid`, `text-danger`) | Validation error summary block, invalid-field borders, error text |

Accent (`btn-primary` blue) reserved for:
- The single **Save** primary action button (`btn btn-primary`)
- Focus rings (`#258cfb` glow already defined in `site.css` for `.form-control:focus` / `.btn:focus`)
- Links/`btn-link` (back link, copy-uid affordance) — already established blue

Accent is NOT used for: secondary actions (Cancel uses `btn-outline-secondary`), field labels, headings, or decorative emphasis. There is exactly **one** primary-blue button on the page (Save).

Semantic color notes:
- **Error/validation** uses Bootstrap danger semantics only: the summary block is `alert alert-danger`, invalid inputs get `is-invalid` (red border + `invalid-feedback` is available but per D-07 v1 surfaces errors in the summary block, not inline). Reuse the exact `alert alert-danger` pattern from Detail/Index error rendering.
- **Success** banner on the detail page (post-303, D-08) uses `alert alert-success` (`--bs-success` `#198754`) — green, dismissible, copy "Role saved" (see Copywriting).
- Disabled/read-only fields (D-04 read-only characteristic, D-05 Uid) render with the `bg-light` secondary surface and `disabled`/`readonly` attribute, matching the muted treatment of `__`-prefixed rows on the Detail page.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Page heading | `Edit {RoleName}` (falls back to `Edit Role` when name is empty, mirroring Detail's `GetPageTitle`) |
| Back / cancel affordance | `← Back to {RoleName}` link styled as `btn btn-link` at top (mirrors Detail's "Back to Roles"); a `Cancel` `btn-outline-secondary` next to Save returns to `/roles/{uid}` |
| Primary CTA | **Save changes** (`btn btn-primary`, `type="submit"`) |
| Uid context label | `UID` shown read-only with copy button (reuse `data-action="copy-uid"`); helper text: `This identifier cannot be changed.` |
| Read-only field hint | `Read-only` muted text/badge beside fields disabled per D-04 characteristic |
| Validation error summary heading | `Please fix the following before saving:` (inside `alert alert-danger`, role="alert"), followed by the list/text of errors returned by `role/isvalid` |
| Empty schema / no editable fields | Heading: `Nothing to edit` · Body: `This role has no editable fields in its schema.` (centered, `text-center mt-5`, `h5 fw-semibold` + `text-muted` — matches Index empty-state pattern) |
| Load error state | Reuse established pattern: `alert alert-danger` with the error message + a recovery link `Back to role` → `/roles/{uid}`. Copy: `Couldn't load this role for editing.` + link. |
| Persist failure (non-validation, HTTP 500/network) | `alert alert-danger`: `Save failed — the change was not stored. Your entries are preserved; try again.` (re-render form with entered values intact per Discretion item). |
| Save success confirmation (on detail page, D-08) | `alert alert-success alert-dismissible`: `Role saved.` — shown on `/roles/{uid}` after the 303 redirect, via a redirect query flag (e.g. `?saved=1`) read by the detail page **(NO TempData — hard constraint D-08)**. |

Destructive actions: **none in this phase.** Editing is non-destructive (no delete, no irreversible operation). No confirmation dialog required. Cancel simply navigates away without a prompt.

Copy voice: terse, operator-facing, sentence case. No exclamation marks except none. Match the existing dry admin tone ("No roles registered", "Showing X–Y of Z roles").

## Interaction Contract

- **Single submit path (D-06):** one POST handler. `role/isvalid` first → if invalid re-render form (422) with the `alert-danger` summary and preserved values, do NOT call persist → if valid call `persist/persist`, then `RedirectToPage` emitted as **303** to `/roles/{uid}?saved=1`.
- **Turbo behavior:** the form is a standard full-page Turbo-driven form submit. The 303 must survive a prior Turbo navigation (the central hazard this phase isolates — validate against the real app early per STATE.md blocker). 422 must re-render the page body so Turbo replaces it with the error state. Antiforgery token must be present in the form so the POST passes validation under Turbo.
- **Focus / accessibility:** error summary has `role="alert"`; invalid inputs marked `aria-invalid="true"`. Save button has an accessible label; on submit, keep the `min-height:44px` target. Reuse the focus-ring style already in `site.css`.
- **No client-side validation, no on-blur (D-06).** No JS framework. The only JS reused is the existing copy-uid delegation in `wwwroot/js/studio.js`.
