## Spacing Scale

Declared values (must be multiples of 4). Expressed as Bootstrap spacing utilities where applicable.

| Token | Value | Bootstrap Utility | Usage |
|-------|-------|------------------|-------|
| xs | 4px | `gap-1`, `p-1` | Icon gaps, badge inner padding, tight inline spacing |
| sm | 8px | `gap-2`, `p-2` | List row internal padding, compact element spacing |
| md | 16px | `gap-3`, `p-3` | Default card padding, column gaps |
| lg | 24px | `gap-4`, `p-4` | Section padding, card group gaps |
| xl | 32px | `gap-5`, `p-5` (Bootstrap 5 uses 3rem ≈ 48px for `5`; use `py-4 px-4` for 32px explicitly) | Layout column gap between sidebar and content |
| 2xl | 48px | `mt-5`, `mb-5` | Major section breaks, empty state vertical centering offset |
| 3xl | 64px | custom `margin: 64px` | Page-level top padding on main content area |

Exceptions:
- Sidebar width (collapsed): 64px fixed — icon rail. Sidebar width (expanded): 240px fixed. These are layout dimensions, not content spacing.
- Scalar side panel width: 480px on desktop (fixed, slides in from right). Not a spacing token — it is a layout constraint.
- Touch targets for scenario card action buttons: minimum 44px height to meet WCAG 2.5.5 (applies to "Open API Docs" button).

## Typography

Bootstrap 5.3.8 default type scale is used directly. No custom font loaded.

| Role | Size | Weight | Line Height | Bootstrap Class / Usage |
|------|------|--------|-------------|------------------------|
| Body | 16px | 400 (regular) | 1.5 | Default `<p>`, scenario description text, tag text |
| Label | 14px | 400 (regular) | 1.4 | `<small>`, secondary metadata (result type, role names), table cell content |

**Constraint:** Only 2 weights used: 400 (regular) and 600 (semibold). Bootstrap renders semibold via `fw-semibold` utility.

## Color

Bootstrap 5.3.8 built-in color-mode system (light mode default; dark mode via `data-bs-theme="dark"`). Colors are expressed as Bootstrap semantic tokens, not hex literals, so they adapt automatically to theme switching.

| Role | Bootstrap Token | Approximate Hex (Light) | Usage |
|------|----------------|------------------------|-------|
| Dominant (60%) | `--bs-body-bg` | `#ffffff` | Page background, main content area surface |
| Secondary (30%) | `--bs-tertiary-bg` | `#f8f9fa` | Sidebar background, scenario cards, category group headers |
| Accent (10%) | `--bs-primary` (Bootstrap blue `#0d6efd`) | `#0d6efd` | See accent reserved list below |
| Destructive | `--bs-danger` | `#dc3545` | No destructive actions exist in Phase 2 — token declared for shell consistency |

**Accent reserved for:**
1. "Open API Docs" button (primary action on each scenario row/card)
2. Active/selected nav item in the sidebar (`.active` class on the Scenarios nav link)
3. Category badge active state (if a category filter is implemented)

Accent is NOT used for: headings, body text, card borders, metadata labels, or tags (those use secondary/muted tokens).

## Layout Contract

**Source:** Phase 1 CONTEXT.md D-01, D-02, D-03; Claude's discretion for Phase 2 specific surfaces.

### Shell (inherited from Phase 1)
- Two-panel Bootstrap flex layout: fixed left sidebar + `flex-grow-1` main content area.
- Sidebar: 240px expanded, 64px icon-rail collapsed. `data-turbo-permanent` on the `<aside>` element.
- Sidebar active nav item: "Scenarios" link is `.active` in this phase.

### Scenario Overview Page (`/scenarios`)
- Full-width main content area below the page title.
- Scenarios rendered as a **vertical list of cards** (`<ul>` of `<li>` items styled as Bootstrap cards or list-group-items). Not a data table — cards allow multi-line content per scenario.
- Each scenario card contains:
  - Row 1: Scenario name (`<h5>`, 20px semibold) + category badge (`<span class="badge">`, right-aligned)
  - Row 2: Result type label (14px, muted) + role names as inline tags (14px, `badge bg-secondary`)
  - Row 3: Tags (if present) as `badge bg-light text-dark` items
  - Action: "Open API Docs" button (`btn btn-primary btn-sm`, 44px min-height) — right-aligned, opens Scalar side panel
- Scenarios grouped by category: rendered as collapsible `<details>/<summary>` accordion sections OR static section headings above each group. Use static headings for v1 (no collapse complexity).
- Category section heading: 14px semibold, muted color (`text-muted`), uppercase letter-spacing, `border-bottom` separator.

### Scalar Side Panel
- Slides in from the right edge of the viewport as a fixed-position overlay panel.
- Width: 480px on desktop (CSS `min(480px, 100vw)`).
- Height: `100vh`, `position: fixed`, `top: 0`, `right: 0`, `z-index: 1055` (above Bootstrap modals at 1050).
- Backdrop: semi-transparent dark overlay behind the panel (`rgba(0,0,0,0.4)`), clicking it closes the panel.
- Panel contains a close button (`btn-close`, top-right corner) and the Scalar mount element.
- Scalar mount: `<div id="scalar-mount">` inside the panel. `data-turbo-permanent` on the outer panel element to persist the Scalar instance across Turbo navigations.
- Scalar init: `Scalar.createApiReference('#scalar-mount', { url: '/openapidoc.json', ... })` called once on `turbo:load`. On panel open, scroll Scalar to the relevant endpoint using Scalar's `onLoaded` callback or URL hash navigation.
- Turbo teardown: no full re-init on every navigation — the `data-turbo-permanent` attribute on the panel preserves the mounted instance. Re-init only if the panel element is missing (first load or hard refresh).
- Panel open/close state managed by toggling a CSS class (`is-open`) on the panel element via vanilla JS (no Alpine, no jQuery).

## States: Scenario Overview Page

All three states must be implemented. Content for each:

### Loading State
- Trigger: while `GET /api/role/director/scenarios` is in flight.
- Implementation: Server-side rendering means this is a Turbo loading indicator (Turbo Drive shows the progress bar automatically). No skeleton UI needed — server renders immediately when response arrives.
- Fallback: If using a Turbo Frame for the scenario list, show a `<p class="text-muted">Loading scenarios…</p>` placeholder inside the frame while the frame loads.

### Empty State
- Trigger: API returns a successful response but the scenarios array is empty.
- Layout: Vertically centered in the main content area, 48px top offset.
- Heading: "No scenarios registered" (20px semibold)
- Body: "The Backlot API returned an empty scenario list. Check that your API is running and has registered scenarios." (16px, muted)
- No CTA button (read-only page; no action to take).

### Error State
- Trigger: API call fails (network error, non-200 response, deserialization failure).
- Layout: Bootstrap `alert alert-danger` block at the top of the main content area, full width.
- Copy: "Could not load scenarios. Check that the Backlot API is reachable at [configured URL] and that your credentials are valid. [Retry link]"
- Retry: Inline anchor link that reloads the page (`href="/scenarios"`).

## Interaction Contract

### Scenario List
- Page load: full-page Turbo Drive navigation to `/scenarios`. Server renders the complete list synchronously.
- Category sections: static — no client-side collapse/expand in v1.
- "Open API Docs" button: click triggers JS to open the Scalar side panel and (if possible) scroll/route to the matching endpoint path. No page navigation — the panel overlays the current page.
- Keyboard: "Open API Docs" button is focusable, `Enter`/`Space` activates it.

### Scalar Side Panel
- Opens: clicking "Open API Docs" on any scenario row adds `is-open` class to `#scalar-panel` and shows the backdrop.
- Closes: clicking the close button or the backdrop removes `is-open`.
- Focus trap: when open, focus is trapped inside the panel. When closed, focus returns to the "Open API Docs" button that opened it.
- Escape key: closes the panel.
- Turbo navigation while panel is open: panel should close before Turbo Drive navigation proceeds (listen for `turbo:before-visit`, remove `is-open`). If navigation is within the same page (frame), panel stays open.
- Scalar re-init guard: check `document.getElementById('scalar-mount').__scalar_initialized` (or equivalent sentinel flag) before calling `createApiReference()` to prevent double-initialization.

### Turbo Specifics
- `data-turbo-permanent` on: `<aside id="sidebar">`, `<div id="scalar-panel">`.
- `<script>` for Scalar CDN: placed in `<head>` via `_Layout.cshtml`. No dynamic script injection.
- `turbo:load` event: listener re-checks sidebar toggle state and Scalar mount state; does NOT re-run `createApiReference()` if already initialized.
