## Spacing Scale

Declared values (must be multiples of 4). Identical to Phase 1 and 2 — no new tokens added.

| Token | Value | Bootstrap Utility | Usage |
|-------|-------|------------------|-------|
| xs | 4px | `gap-1`, `p-1` | Icon gaps, badge inner padding, copy-to-clipboard icon gap |
| sm | 8px | `gap-2`, `p-2` | Row internal padding, compact element spacing |
| md | 16px | `gap-3`, `p-3` | Default card padding, column gaps, field row spacing |
| lg | 24px | `gap-4`, `p-4` | Section padding, detail card internal padding |
| xl | 32px | explicit `32px` | Layout column gap between sidebar and content |
| 2xl | 48px | `mt-5`, `mb-5` | Empty state vertical centering offset |
| 3xl | 64px | custom `margin: 64px` | Page-level top padding on main content area |

Exceptions:
- Sidebar dimensions (240px / 64px) are layout constraints carried from Phase 1.
- All interactive affordances (search clear button, copy-to-clipboard button, pagination buttons, Edit button): minimum 44px height to meet WCAG 2.5.5.
- Pagination control row: 8px gap between page buttons (`gap-2`).

**Source:** Phase 1 and 2 UI-SPECs (spacing scale inherited unchanged).

## Color

Bootstrap 5.3.8 semantic tokens (light mode default). Colors adapt automatically to dark mode via the built-in color-mode system.

| Role | Bootstrap Token | Approximate Hex (Light) | Usage |
|------|----------------|------------------------|-------|
| Dominant (60%) | `--bs-body-bg` | `#ffffff` | Page background, main content area, field value cells |
| Secondary (30%) | `--bs-tertiary-bg` | `#f8f9fa` | Sidebar background, role list row hover state, detail page field key column background |
| Accent (10%) | `--bs-primary` (`#0d6efd`) | `#0d6efd` | See accent reserved list below |
| Destructive | `--bs-danger` | `#dc3545` | API error alerts; no destructive actions exist in Phase 3 |

**Accent reserved for:**
1. Active sidebar nav item ("Roles" link — `.active` class, `text-primary fw-semibold`)
2. "Edit Role" button — `btn btn-primary` — only rendered when `__Permission.CanWrite` is true
3. Related role row links (underline on hover via standard `<a>` anchor color)
4. Pagination active page button (`btn btn-primary`)
5. Search submit button (`btn btn-primary`)

Accent is NOT used for: role list row backgrounds, field labels, `__Permission` badges (those use `bg-secondary`/`bg-success`/`bg-danger` semantics — see Badge section below), `__Skills` badges, copy-to-clipboard icon, pagination non-active buttons, search input border.

**Permission badge color mapping (semantic, not accent):**

| Flag | Value = true | Value = false |
|------|-------------|--------------|
| CanCreate | `badge bg-success` (green) | `badge bg-secondary` (muted) |
| CanRead | `badge bg-success` (green) | `badge bg-secondary` (muted) |
| CanWrite | `badge bg-success` (green) | `badge bg-secondary` (muted) |

**Source:** Phase 1 and 2 UI-SPECs (color system inherited); Claude's discretion for badge semantics.

## Layout Contract

### Shell (inherited from Phase 1)
- Fixed left sidebar (240px expanded / 64px collapsed, `data-turbo-permanent`).
- Active sidebar nav item in this phase: "Roles" (`<a href="/roles">` with `.active fw-semibold text-primary`).
- The "Roles" sidebar link that was `disabled` in Phases 1 and 2 is upgraded to a functional link in Phase 3.

### Role List Page (`/roles`)

**URL:** `/roles`

- Page title heading: "Roles" (`<h4 class="fw-semibold mb-4">`)
- Layout: single-column full-width within main content area.

**Search / Filter bar** (above the list):
- One row: text input (`<input type="text" class="form-control">`) + "Search" submit button (`btn btn-primary`) + clear affordance.
- Clear affordance: when a search term is active, render an `<a>` anchor or a second small `btn btn-outline-secondary` button labeled "Clear" to the right of the search button. Navigates to `/roles` (no criteria).
- Below the search bar: result count line — `<small class="text-muted">Showing X–Y of Z roles</small>`.
- The entire search bar + result count is inside a `<turbo-frame id="role-list">` so that search submissions and pagination clicks update only the list region without a full page reload.

**Role list:**
- Rendered as a Bootstrap `<table class="table table-hover">` with columns: UID (truncated, monospace), Role Type, fields summary (top 2–3 visible field keys as comma-separated labels), and Actions.
- Each row: UID cell contains a copy-to-clipboard icon button (`<button>` with `bi bi-clipboard` icon, 44px min-height). The UID value is truncated to 12 characters with a `title` tooltip showing the full UID.
- Actions column: "View" button (`btn btn-outline-secondary btn-sm`, 44px min-height) linking to `/roles/{uid}`. No "Edit" action on the list — Edit is on the detail page only.
- Table is inside the `<turbo-frame id="role-list">`.

**Pagination:**
- Below the table, inside the `<turbo-frame id="role-list">`.
- Bootstrap pagination component (`<nav aria-label="Role list pages"><ul class="pagination">`) with Previous, numbered pages (or page indicator), and Next buttons.
- Active page: `btn btn-primary` or `<li class="page-item active">`. Non-active: `btn btn-outline-secondary` or standard `<li class="page-item">`.
- Page size: 25 roles per page (fixed, not configurable in v1).
- Pagination renders only if total count > 25.

### Role Detail Page (`/roles/{uid}`)

**URL:** `/roles/{uid}`

- Page title heading: role type name from the API response (`<h4 class="fw-semibold mb-3">`), e.g., "Product".
- Sub-heading line: UID value in `<code>` element + copy-to-clipboard button (`bi bi-clipboard`, 44px min-height). Example: `<code class="text-muted small">uid-abc-123...</code>`.
- Edit affordance: `<a href="/roles/{uid}/edit" class="btn btn-primary">Edit Role</a>` — rendered only when `__Permission.CanWrite` is true. When false: rendered as `<button class="btn btn-outline-secondary disabled" disabled aria-disabled="true">Edit Role</button>` (visible but disabled, not hidden — matches ROLE-03 "hidden or disabled").
- Back link: `<a href="/roles" class="btn btn-link p-0 mb-3"><i class="bi bi-arrow-left me-1"></i>Back to Roles</a>` above the heading.

**Fields section:**
- Heading: `<h5 class="fw-semibold mt-4 mb-2">Fields</h5>`
- Rendered as a Bootstrap definition-list-style table: two columns, "Field" (key) and "Value".
- Table: `<table class="table table-sm table-bordered">` with `<tbody>`.
- Field key column: 30% width, `bg-light` (maps to `--bs-tertiary-bg`), `<code>` for field name, 14px.
- Field value column: 70% width, 16px body text. Long strings wrap; no truncation in detail view.
- `__Permission` and `__Skills` system fields are rendered at the top of the table, above user-defined fields, separated by a visually distinct row or minor heading.

**`__Permission` row:**
- Rendered as three inline badges in the value cell: `CanCreate`, `CanRead`, `CanWrite`.
- Badge color: green (`bg-success`) for true, muted (`bg-secondary`) for false. Text is `text-white` for both.
- Example: `<span class="badge bg-success me-1">CanRead</span><span class="badge bg-secondary me-1">CanCreate</span>`

**`__Skills` row:**
- Rendered as one inline badge per skill in the value cell.
- Badge style: `badge bg-light text-dark border` (light background, visible border, dark text). No semantic color — skills are informational labels only.
- If `__Skills` is empty or absent: render `<span class="text-muted small">None</span>`.

**Related Roles section:**
- Heading: `<h5 class="fw-semibold mt-4 mb-2">Related Roles</h5>`
- Content loaded lazily via a Turbo Frame: `<turbo-frame id="related-roles" src="/roles/{uid}/relations" loading="lazy">`.
- Frame loading state placeholder (rendered inside the frame by the server before the lazy src loads): `<p class="text-muted small">Loading related roles…</p>`.
- Once loaded, renders as a compact `<table class="table table-sm table-hover">` with columns: Relation Type, Role Type, UID (truncated), and a "View" link.
- Each row's "View" link navigates to `/roles/{related-uid}` as a standard Turbo Drive navigation (not a frame navigation).
- If no relations: `<p class="text-muted small">No related roles.</p>`.

## States

### Role List Page States

#### Default (results present)
- Search bar empty. Result count visible. Table populated. Pagination shown if > 25 results.

#### Searching (criteria active)
- Search input shows the active query. "Clear" affordance visible. Result count reflects filtered total. Table shows filtered rows. If filtered count ≤ 25, pagination is hidden.

#### Empty (no roles found)
- Trigger: API returns an empty result set (total = 0), either from the base query or from a search filter.
- Layout: inside the `<turbo-frame id="role-list">`, below the search bar.
- If searching: heading "No roles match your search", body "Try a different search term or [Clear search] to see all roles."
- If not searching: heading "No roles registered", body "The Backlot API returned no persisted roles. Roles appear here after scenarios that create them have been executed."
- No CTA button (read-only page).

#### Error (API failure)
- Trigger: `simplequery/find` call returns a non-200 response or throws.
- Layout: Bootstrap `alert alert-danger` block at the top of the main content area (outside the Turbo Frame so it is always visible).
- Copy: "Could not load roles. Check that the Backlot API is reachable and that your credentials are valid. [Retry]"
- Retry: inline `<a href="/roles" class="alert-link">Retry</a>`.

### Role Detail Page States

#### Default (loaded)
- All field rows rendered. `__Permission` and `__Skills` badges rendered. Related roles Turbo Frame loading (lazy).

#### Related roles loading
- `<p class="text-muted small">Loading related roles…</p>` inside the `<turbo-frame id="related-roles">`.

#### Related roles empty
- `<p class="text-muted small">No related roles.</p>` inside the frame once loaded.

#### Error (detail fetch failure)
- Trigger: `seekbase/detail` call fails (non-200 or network error).
- Layout: Bootstrap `alert alert-danger` at the top of the page content area.
- Copy: "Could not load role details. The role may not exist or the API may be unavailable. [Back to Roles]"
- "Back to Roles" is an anchor link to `/roles`.

#### Related roles error
- Trigger: `persist/relations` call fails for the frame.
- Inside the `<turbo-frame id="related-roles">`: `<div class="alert alert-warning alert-sm">Could not load related roles. <a href="/roles/{uid}">Retry</a></div>`.
- Warning (`alert-warning`, not `alert-danger`) because failing to load relations is not fatal to the detail page.

## Interaction Contract

### Role List Page

**Search / Filter:**
- Submit: form `POST` or `GET` to `/roles?q={query}&page=1`. The `<turbo-frame>` targets itself (the frame `src` changes to the filtered URL). Server-side: PageModel reads `q` query param, builds `Criteria`, calls `simplequery/find`.
- Clear: navigate to `/roles` (no query params) — clears filter and resets to page 1.
- The search form is inside the Turbo Frame so that submission replaces only the list+pagination without a full page reload. The search bar itself persists (renders server-side with the active query value filled in).
- Keyboard: `Enter` in the search input submits the form. `Tab` moves focus to the Search button, then Clear (if visible).

**Pagination:**
- Each pagination link navigates via a Turbo Frame `src` update: `/roles?q={query}&page={n}`.
- The frame updates in-place. The URL in the browser address bar updates via `data-turbo-action="advance"` on the frame (so Back/Forward navigate paginated results correctly).

**Copy UID:**
- A `<button>` with `bi bi-clipboard` icon alongside the UID cell in the list (and in the detail heading).
- Click: calls `navigator.clipboard.writeText(uid)`. On success: swap icon to `bi bi-clipboard-check` and show a `<span class="visually-hidden">Copied!</span>` announcement (for screen readers) + a brief visible tooltip or label swap to "Copied!" — revert after 1500ms.
- On failure (clipboard not available): silently fail (no error toast) — the UID is already visible and the user can manually select and copy it.
- No inline JS in HTML attributes. Event listener wired in `studio.js` via `turbo:load` using event delegation on `[data-action="copy-uid"]` attribute.

**View Role:**
- "View" button in the list table navigates to `/roles/{uid}` via standard Turbo Drive `<a>` link with `data-turbo-action="advance"`.

### Role Detail Page

**Lazy Related Roles Frame:**
- `<turbo-frame id="related-roles" src="/roles/{uid}/relations" loading="lazy">` triggers an automatic fetch when the frame enters the viewport.
- The partial view (`/roles/{uid}/relations`) returns a `<turbo-frame id="related-roles">` containing the relations table or empty/error state.
- Related role "View" links inside the frame navigate full-page (standard Turbo Drive, `data-turbo-frame="_top"` to escape the frame).

**Edit affordance:**
- When `CanWrite = true`: `<a href="/roles/{uid}/edit" class="btn btn-primary">Edit Role</a>`.
- When `CanWrite = false`: `<button class="btn btn-outline-secondary" disabled aria-disabled="true">Edit Role</button>`. Rendered as a `<button>` (not `<a>`) to ensure the disabled attribute is honoured by assistive technology.

**Copy UID (detail page):**
- Same interaction as list page. The UID appears in the sub-heading line as `<code>` + copy button. Also repeated as a field row in the Fields table (the `Uid` or `__Uid` field).

### Turbo Specifics

- `data-turbo-permanent` on: `<aside id="sidebar">`, `<div id="scalar-panel">` (unchanged from Phase 2).
- `data-turbo-action="advance"` on: the `<turbo-frame id="role-list">` for pagination and search, so that pagination steps are browser-history entries.
- `data-turbo-frame="_top"` on: related role "View" links (to escape the `related-roles` frame and do a full-page navigation).
- No new `data-turbo-permanent` elements added in Phase 3.
- `turbo:load` listener in `studio.js`: wire copy-to-clipboard event delegation (via `[data-action="copy-uid"]` on buttons). No Scalar re-init needed for Phase 3 pages (Scalar panel is only opened from the Scenarios page).
