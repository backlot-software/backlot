<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser→Studio (Razor Pages) | Search query param `q` and `page` are untrusted user input; bound via [FromQuery] |
| Studio→Backlot API | POST bodies constructed server-side from validated inputs; credentials injected by BasicAuthHandler |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | FindRequest.Criteria built from `q` query param | mitigate | Server-side string split only; no eval, no SQL; posted as structured JSON to Backlot API which performs its own validation |
| T-03-02 | Information Disclosure | UID values rendered in HTML, `data-uid` attribute | accept | UIDs are non-secret identifiers; they are already visible in the list; no PII in UID itself |
| T-03-03 | Spoofing | Clipboard write via navigator.clipboard.writeText | accept | Clipboard access requires user gesture (click); no cross-origin exposure |
| T-03-04 | Tampering | localStorage column config key studio_columns_{skill} | accept | Developer-only tool; no server-side trust placed in localStorage values; used only for column display preferences |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan; all assets are CDN-pinned from Phase 1–2 |
</threat_model>
