## Spacing Scale

Declared values (must be multiples of 4). Expressed as Bootstrap spacing utilities where applicable.

| Token | Value | Bootstrap Utility | Usage |
|-------|-------|------------------|-------|
| xs | 4px | `gap-1`, `p-1` | Icon gaps, badge inner padding, tight inline spacing |
| sm | 8px | `gap-2`, `p-2` | Input label gap, compact element spacing |
| md | 16px | `gap-3`, `p-3` | Default card padding, form field spacing |
| lg | 24px | `gap-4`, `p-4` | Login card internal padding, section padding |
| xl | 32px | `gap-5` / explicit `32px` | Sidebar content vertical rhythm |
| 2xl | 48px | `mt-5`, `mb-5` | Login card vertical centering offset from viewport center |
| 3xl | 64px | custom `margin: 64px` | Page-level top padding on main content area |

Exceptions:
- Sidebar width (collapsed): 64px fixed — icon rail. Sidebar width (expanded): 240px fixed. These are layout dimensions, not content spacing tokens.
- Login card max-width: 400px centered horizontally. Layout constraint, not a spacing token.
- Sidebar toggle button minimum tap target: 44px × 44px (WCAG 2.5.5).

**Source:** CONTEXT.md D-01, D-03; Phase 2 UI-SPEC spacing scale (shared baseline).

## Color

Bootstrap 5.3.8 built-in color-mode system (light mode default; dark mode via `data-bs-theme="dark"`). Colors are expressed as Bootstrap semantic tokens, not hex literals, so they adapt automatically to theme switching.

| Role | Bootstrap Token | Approximate Hex (Light) | Usage |
|------|----------------|------------------------|-------|
| Dominant (60%) | `--bs-body-bg` | `#ffffff` | Page background, main content area surface, login page background |
| Secondary (30%) | `--bs-tertiary-bg` | `#f8f9fa` | Sidebar background, login card background (`bg-light` or `card` default) |
| Accent (10%) | `--bs-primary` (Bootstrap blue `#0d6efd`) | `#0d6efd` | See accent reserved list below |
| Destructive | `--bs-danger` | `#dc3545` | Invalid-credentials error alert (`alert-danger`) |

**Accent reserved for:**
1. Login form submit button ("Sign in" — `btn btn-primary`)
2. Active/selected nav item in the sidebar (`.active` class — applied to the placeholder nav item for the current phase, none active in Phase 1 shell)
3. Sidebar toggle button focus ring (browser default via Bootstrap focus styles)

Accent is NOT used for: headings, body text, card borders, username display text, disabled nav links, or the logout link (those use secondary/muted tokens).

**Source:** Phase 2 UI-SPEC color system (shared baseline); CONTEXT.md D-06, D-07.

## Layout Contract

**Source:** CONTEXT.md D-01 through D-09.

### Login Page (`/login`)
- Full-page centered layout. No sidebar visible.
- Outer: `d-flex justify-content-center align-items-center min-vh-100` on `<body>` or a wrapping `<div>`.
- Login card: Bootstrap `card` component, `max-width: 400px`, `w-100` with horizontal margin auto.
- Card structure:
  - Card header or card body top: "Backlot Studio" as `<h4>` (28px semibold, `text-center`).
  - Below heading: username `<input type="text">` + password `<input type="password">` stacked vertically with `mb-3` spacing.
  - Labels: Bootstrap `<label class="form-label">` above each input.
  - Submit button: `<button type="submit" class="btn btn-primary w-100">Sign in</button>` — full card width.
  - Error alert: `<div class="alert alert-danger" role="alert">` — rendered above the form fields when credentials are invalid. Copy: "Invalid username or password."
- No sidebar, no top navbar, no footer on the login page.

### Authenticated Shell (`_Layout.cshtml`)
- Two-panel Bootstrap flex layout: `d-flex` on `<body>` or a root wrapper, with a fixed-width `<aside>` sidebar and a `flex-grow-1` main content area.
- Sidebar element: `<aside id="sidebar" data-turbo-permanent>` — `data-turbo-permanent` preserves collapse state across Turbo Drive navigations.
- Top horizontal bar: absent — no top navbar. Identity and logout live in the sidebar per D-08.

### Sidebar (Expanded: 240px / Collapsed: 64px icon rail)
- Fixed left sidebar. CSS `position: fixed; left: 0; top: 0; height: 100vh; width: 240px;` expanding to full height. Main content area has `margin-left: 240px` (or `64px` when collapsed).
- Sidebar sections (top to bottom):
  1. **App name** (top): "Backlot Studio" in 14px semibold (`fw-semibold`) — hidden in collapsed icon-rail mode (show icon only).
  2. **Nav items** (middle, scrollable): Placeholder links for "Scenarios" and "Roles" — rendered as `disabled` `<a>` tags or `<span>` elements with `.nav-link.disabled` class and muted text. No active state in Phase 1 (no target pages yet).
  3. **Identity block** (bottom): Username string (from `whoami` response, 14px regular, `text-muted`) + "Sign out" link (`<a href="/logout">Sign out</a>`, 14px, not styled as button) below the username. In collapsed mode: show user icon (`bi-person-circle`) only, tooltip shows username.
- Toggle button: `<button id="sidebar-toggle">` at the top of the sidebar with a hamburger icon (`bi-list`, 24px). Clicking it toggles a CSS class (`.sidebar-collapsed`) on `<body>` or `<html>`. CSS handles the width transition via `transition: width 0.2s ease`.
- Toggle animation: `width` CSS transition, 200ms, `ease` easing. No transform/translate animation — width-only for simplicity.
- Collapsed icon rail: sidebar shows only icons (no text labels). Nav icons: `bi-play-circle` for Scenarios placeholder, `bi-boxes` for Roles placeholder. Toggle icon: `bi-list` (hamburger).

**Source:** CONTEXT.md D-01, D-02, D-03, D-08, D-09.

## States

### Login Page States

#### Default (no error)
- Login card rendered with empty inputs, no alert visible.

#### Error State (invalid credentials)
- `<div class="alert alert-danger mt-3" role="alert">Invalid username or password.</div>` rendered above the form fields (inside the card, before the username input).
- Form inputs retain their empty or submitted values so the user does not need to re-type the username.
- No field-level highlighting on individual inputs (Basic Auth does not differentiate which field is wrong — per D-07).

#### Submitting State
- Submit button disabled and label changed to "Signing in…" while the POST is in flight (Turbo Drive handles this automatically via `data-turbo-submits-with` or manual JS disabling on form submit).

### Sidebar States

#### Expanded
- Full 240px width. All nav text labels visible. App name visible. Username and "Sign out" visible.

#### Collapsed (icon rail)
- 64px width. Icons only. App name hidden. Nav text hidden. Username replaced by `bi-person-circle` icon with `title` tooltip showing the username. Toggle icon switches from `bi-list` to `bi-arrow-bar-left` (or `bi-arrow-bar-right` when collapsed, to indicate "expand").

#### Unauthenticated (no session)
- Sidebar is not rendered. Full-page login layout used instead.

## Interaction Contract

### Login Form
- Method: `POST /login` (Razor Pages handler `OnPostAsync`).
- On success: redirect (302) to `/` (authenticated shell root — which will redirect to the first available page; in Phase 1 that is a minimal index or `/scenarios` placeholder).
- On failure (invalid credentials): re-render login page with `alert-danger` block. HTTP 200 re-render — not a redirect.
- No client-side JS validation on the login form. Server-side only.
- Antiforgery token: included via `@Html.AntiForgeryToken()` (standard Razor Pages `asp-page` form tag handles this automatically).

### Logout
- `GET /logout` or `POST /logout` handler: clears `ISession` and signs out cookie auth. Redirects to `/login`.
- Prefer `POST /logout` with antiforgery to prevent CSRF-triggered logout via `<img>` or `<a>` link. Logout link in sidebar submits a minimal form: `<form method="post" action="/logout"><button class="btn btn-link p-0">Sign out</button></form>`.

### 401 Mid-Session Redirect
- When `BasicAuthHandler` receives a 401 from the Backlot API, the service layer sets a flag or throws a typed exception.
- Middleware or a base PageModel catches this and calls `Response.Redirect("/login", permanent: false)`.
- Redirect must target the top-level document, not a Turbo Frame. Use `Response.Headers["Turbo-Visit-Control"] = "reload"` or emit a Turbo Stream `<turbo-stream action="visit" url="/login">` to force full-page navigation if inside a frame.

### Sidebar Toggle
- Click `#sidebar-toggle`: toggles `.sidebar-collapsed` class on `<body>`. CSS handles the width transition.
- State persistence across Turbo navigations: because `<aside data-turbo-permanent>` is used, the sidebar element (including its expanded/collapsed class) is preserved across Turbo Drive page changes. No `localStorage` needed.
- Keyboard: toggle button is focusable, `Enter`/`Space` activates it.

### Whoami
- Called once on authenticated page load from the server side (PageModel `OnGetAsync`) and passed to `_Layout.cshtml` via `ViewData["Username"]`. Not called client-side.
- If `whoami` fails (network error or 401), fallback display: show "Unknown user" in the sidebar identity block.

### Turbo Specifics
- `data-turbo-permanent` on: `<aside id="sidebar">`.
- Login page: `data-turbo="false"` on the login form to prevent Turbo Drive from intercepting the POST (auth forms must not be turbo-submitted in v1 to avoid session/cookie race conditions).
- `turbo:load` listener: re-checks sidebar toggle state. No re-initialization needed for Phase 1 (no Scalar in this phase).
