  <name>Task 1: Add PlayAsync + PlayAllowingClientErrorAsync primitives to interface and client</name>
  <files>Backlot.Studio/Services/IBacklotApiClient.cs, Backlot.Studio/Services/BacklotApiClient.cs</files>
  <action>
Add three new public members to the interface `IBacklotApiClient` (in addition to all existing members, which stay unchanged):
- `Task<ApiEnvelope<T>?> PlayAsync<T>(string roleName, string scenario, string? uid = null, CancellationToken ct = default)` — the GET overload.
- `Task<ApiEnvelope<T>?> PlayAsync<T>(string roleName, string scenario, object body, CancellationToken ct = default)` — the POST overload.
- `Task<ApiEnvelope<T>?> PlayAllowingClientErrorAsync<T>(string roleName, string scenario, object body, CancellationToken ct = default)`.

Implement them in `BacklotApiClient` as public methods that replace the two private helpers `GetEnvelopeAsync<T>` and `PostEnvelopeAsync<T>` (delete those two private helpers in Task 2 once callers are rewired — for this task, you may add the new methods alongside them).

GET `PlayAsync<T>(roleName, scenario, uid, ct)`:
- Build the base path as `api/role/{roleName}/{scenario}`.
- Append the query only when `uid` is non-empty: when `string.IsNullOrEmpty(uid)` is false, append `?uid=` followed by `Uri.EscapeDataString(uid)`. When uid is null/empty, issue no query string at all. This mirrors the GET branch in `ApplicationBuilding.cs`: director scenarios pass no uid; other roles require uid as the only query param. (Today every GET caller passes no uid, so the produced paths must remain byte-for-byte identical to the current literal strings such as `api/role/director/isauthenticated`.)
- Call `_httpClient.GetAsync(path, ct)`, then `EnsureSuccessAsync(response, ct)`, then `response.Content.ReadFromJsonAsync<ApiEnvelope<T>>(JsonOptions, ct)`. Return the result.

POST `PlayAsync<T>(roleName, scenario, body, ct)`:
- Build path `api/role/{roleName}/{scenario}`.
- Call `_httpClient.PostAsJsonAsync(path, body, JsonOptions, ct)`, then `EnsureSuccessAsync(response, ct)`, then `ReadFromJsonAsync<ApiEnvelope<T>>(JsonOptions, ct)`. Return the result.

`PlayAllowingClientErrorAsync<T>(roleName, scenario, body, ct)`:
- Build path `api/role/{roleName}/{scenario}` and POST via `PostAsJsonAsync(path, body, JsonOptions, ct)`.
- Move the EXACT 4xx-recovery logic currently inline in `ValidateRoleAsync` here, generalized over `T`: compute `isClientValidationFailure` as status in [400,500) AND not Unauthorized AND not Forbidden. If not success and not a client validation failure, call `EnsureSuccessAsync`. If it is a client validation failure, try `ReadFromJsonAsync<ApiEnvelope<T>>(JsonOptions, ct)` inside a `try/catch (JsonException)` and return that envelope when its `Body` is non-null; on `JsonException` fall through to `EnsureSuccessAsync` (rich throw). On success, deserialize and return the envelope normally. Preserve the explanatory comment intent (WR-02): 401/403 and 5xx still throw; structured 4xx body is recovered.

Keep `EnsureSuccessAsync`, `BacklotApiException`, `JsonOptions`, and the WR-04/WR-05 comments exactly as-is. Use the shared `JsonOptions` instance for all (de)serialization. Do NOT place fenced code blocks in comments.

Rewrite each typed method to delegate to the new primitives, then delete the now-unused private `GetEnvelopeAsync<T>` and `PostEnvelopeAsync<T>` helpers. Preserve each method's existing public signature and its explanatory comment intent.

- `IsAuthenticatedAsync` → `await PlayAsync<bool>("director", "isauthenticated")`; return `envelope?.Body ?? false`.
- `WhoAmIAsync` → `await PlayAsync<object>("director", "whoami")`; return `envelope?.Body`.
- `GetScenariosAsync` → `await PlayAsync<IEnumerable<ScenarioItem>>("director", "scenarios")`; return `envelope?.Body`.
- `GetRoleSchemaAsync` → `await PlayAsync<IReadOnlyList<RoleSchema>>("director", "roles", ct: ct)`; return `envelope?.Body`. (Pass `ct` by name since the GET overload's third positional param is `uid`.)
- `FindRolesAsync` → `await PlayAsync<FindResult>("simplequery", "find", request, ct)`; return `envelope?.Body`.
- `GetRoleRelationsAsync` → `await PlayAsync<IEnumerable<RelationItem>>("persist", "relations", new { Uid = uid }, ct)`; return `envelope?.Body`.
- `PersistRoleAsync` → `await PlayAsync<JsonElement>("persist", "persist", roleData, ct)`; return `envelope?.Body`.
- `GetRoleDetailAsync` → `await PlayAsync<JsonElement>("seekbase", "detail", new { For = uid }, ct)`; if envelope is null return null; otherwise return `UnwrapRoleDetail(envelope.Body)`. Keep `UnwrapRoleDetail` and its comment exactly as-is (WR-03 unwrap chokepoint preserved).
- `ValidateRoleAsync` → `var envelope = await PlayAllowingClientErrorAsync<ValidationOutcome>("role", "isvalid", roleData, ct); return envelope?.Body;`. The structured 4xx recovery now lives in the primitive and must remain intact (WR-02).

After rewiring, remove `GetEnvelopeAsync<T>` and `PostEnvelopeAsync<T>` — no caller should remain. Confirm the rolename/scenario tokens used in each wrapper exactly match the literal path segments from the original code (director/isauthenticated, director/whoami, director/scenarios, director/roles, simplequery/find, persist/relations, persist/persist, seekbase/detail, role/isvalid) so the issued HTTP requests stay byte-for-byte equivalent.
